# Codex Pro 用户反馈分流指南

## 1. 目的

这份指南用于 `Codex Pro v0.2.5` GitHub 首发后的首批 issue 分流。

目标不是把每个反馈都变成临时手工排查，而是快速判断问题属于：

- 用户环境或安装路径问题。
- Codex Desktop 更新或显示条件变化。
- 本地历史数据边界。
- 安装 / 更新 / 卸载问题。
- 页面增强或兼容模式问题。
- Codex Pro 自身 bug。
- 后续版本功能诉求。

同时，这份指南也用来防止首发后因为用户需求扩张，把 `Codex Pro` 拉成插件市场、云同步工具、provider 管理器、上下文破限工具或全能管理器。

## 2. issue 类型

首批反馈按下面类型分流：

| 类型 | 用途 | 优先入口 |
| --- | --- | --- |
| 安装失败 | 安装脚本报错、入口未创建、依赖检查不通过 | Bug 报告 |
| 更新失败 | 检查更新失败、安装更新失败、回滚提示 | Bug 报告 |
| 卸载失败 | 原生 Codex 入口未恢复、维护入口未移除 | Bug 报告 |
| 历史不显示 | CLI 或本地文件仍在，但 Desktop 侧看不到 | Desktop 历史会话不显示 |
| 历史真丢失 | 本地会话文件、索引或快照都找不到 | Bug 报告 |
| 兼容模式疑问 | 用户误以为 compatibility mode 是失败 | 使用问题 / 恢复路径咨询 |
| UI 注入异常 | `历史` 入口、面板、删除撤销或高级区没有按预期出现 | Bug 报告 |
| 删除 / 撤销异常 | 单会话删除、撤销恢复、当前会话保护异常 | Bug 报告 |
| 导出异常 | 单会话 Markdown 导出失败或内容异常 | Bug 报告 |
| Handoff 异常 | 本地交接包生成失败或缺少关键信息 | Bug 报告 |
| 插件入口修复异常 | 高级区插件入口 / 安装按钮可见性修复不符合预期 | Bug 报告 |
| Codex++ parity 诉求 | 想要 Codex++ 某能力在 Codex Pro 中出现 | 使用问题 / 功能请求 |
| 安全 / 隐私疑问 | 担心上传、账号、密钥、配置或本地 bridge | 使用问题 / 恢复路径咨询 |
| 功能请求 | 不属于 v0.2.5 已验证能力的新需求 | 使用问题 / 功能请求 |

## 3. 必要信息

维护者优先索取下面信息。不要一开始就要求用户上传数据库、完整历史目录或登录文件。

- Codex Pro 版本，例如 `v0.2.5`。
- Windows 版本。
- Codex Desktop 版本或大概更新时间，如可得。
- 安装方式：release 包、仓库源码、npm 包或其它。
- 当前模式：`takeover_injection`、`takeover_compatibility`、`maintenance`、未知。
- `codex-pro status` 输出，或 `历史` 面板中的状态区文本。
- 是否还能继续正常打开 `Codex`。
- 是否已经点击 Codex 内的 `历史`。
- 是否按固定三步操作：
  1. 修复历史显示
  2. 重建历史索引
  3. 打开高级修复
- 是否切换过 provider、`base_url` 或账号。
- 是否看到 `encrypted_content` 相关提示。
- 日志路径可以提供，但不要直接贴敏感内容。

## 4. 绝对不要让用户贴

issue、discussion、截图和日志片段里都不应包含：

- `auth.json` 原文。
- API Key。
- Bearer token。
- session token。
- `encrypted_content` 原文。
- 完整本地历史文件。
- 私有代理 URL 中的 token query。
- 账号凭据。
- 云服务凭据。
- Cookie。
- 私有环境变量。

如果用户已经贴出敏感内容，应先要求用户删除或轮换对应凭据，再继续排查。

## 5. P0 / P1 / P2 / P3 triage 标准

| 等级 | 标准 | 处理方式 |
| --- | --- | --- |
| P0 | 可能破坏历史、误删、上传风险、无法卸载恢复入口、安全边界破坏 | 暂停发布扩散，先确认复现路径和最小修复 |
| P1 | 安装失败、更新失败、主路径不可用、真实 UI 完全不可用且不能安全回退 | 优先修复或给出临时规避步骤 |
| P2 | 单功能异常、文案不清、部分环境兼容差、planned 能力被误解 | 进入近期修复或文档澄清 |
| P3 | 功能请求、平台扩展、外观建议、长期 parity 诉求 | 进入 roadmap / parity 评估，不承诺首发完成 |

## 6. 处理原则

1. 先判断用户是否仍能继续正常打开 `Codex`。
2. 先判断 compatibility fallback 是否正常，不要把兼容模式当失败。
3. 先要 `status` 或面板状态文本，不要直接要数据库。
4. 先确认本地数据是否还在，再判断是否真丢失。
5. 先走固定三步：修复历史显示 → 重建历史索引 → 打开高级修复。
6. 不建议用户手改 `provider`、`base_url` 或登录方式来配合排查。
7. 不承诺跨 `encrypted_content` 边界恢复可继续对话的旧内容。
8. 不把 roadmap 里的 planned 能力当成 v0.2.5 bug。
9. 更新问题必须确认是否已经回滚到当前可用版本。
10. 卸载问题必须先确认 Codex 历史、快照和仓库代码是否仍保留。

## 7. 回复模板

### 安装失败

```text
谢谢反馈。请先确认你是否还能像平常一样打开 Codex。

为了判断是依赖、权限还是入口接管问题，请补充：
1. Codex Pro 版本
2. Windows 版本
3. 安装方式
4. 安装脚本最后 30 行输出
5. 是否已经生成 Codex Pro.cmd 或开始菜单 Codex Pro 文件夹

请不要贴 auth.json、密钥、token 或 encrypted_content 原文。
```

### 历史不显示

```text
这类问题先按“历史显示问题”处理，不一定代表历史真丢失。

请先继续正常打开 Codex，点“历史”，按固定三步试一次：
1. 修复历史显示
2. 重建历史索引
3. 打开高级修复

如果仍不完整，请贴 codex-pro status 输出或“历史”面板状态文本，不要贴完整历史文件。
```

### 兼容模式疑问

```text
compatibility mode 是安全回退，不是安装失败。

当前环境如果暂时不能挂上页面增强，Codex Pro 仍应保留历史保护、快照、修复历史显示、重建历史索引和维护入口。

请确认：
1. 是否还能正常打开 Codex
2. 是否能打开开始菜单里的 Codex Pro 维护入口
3. status 里显示的当前模式是什么
```

### Codex++ parity 功能请求

```text
这个能力会按 Codex++ parity 矩阵评估，但 v0.2.5 不承诺全量 parity。

Codex Pro 会优先保持原生感、低门槛、安全边界和历史恢复主路径。请补充你需要这个能力解决的真实场景，我们会判断它属于第一层、第二层、高级区还是后续版本。
```

### 安全疑问

```text
Codex Pro 的首发边界是本地优先：不上传历史、账号数据、auth.json 或 encrypted_content 原文，也不会自动改 model_provider、base_url 或登录方式。

如果你担心某段输出含敏感信息，请先不要公开粘贴，描述字段名或贴脱敏后的片段即可。
```

### 更新失败

```text
请先确认当前版本是否仍能继续使用。

Codex Pro 的更新安装应由用户确认触发，不做静默安装；更新前会备份当前版本，失败后应回滚到当前可用版本。

请补充：
1. 当前版本和目标版本
2. Update Codex Pro.cmd 或 codex-pro update 的输出
3. 是否看到“已恢复当前版本，Codex Pro 仍可继续使用”类似提示
```

### 卸载恢复

```text
卸载默认不删除 Codex 历史、历史快照或仓库代码。

请确认：
1. 卸载脚本是否提示恢复原生 Codex 入口
2. 现在桌面或开始菜单的 Codex 是否能打开
3. 是否使用过 -RemoveData
4. 卸载输出里是否有失败步骤

不要上传完整历史目录或登录文件。
```

## 8. 发布后前 7 天观察指标

发布后优先观察：

- 安装失败数量和失败阶段。
- 兼容模式反馈比例。
- 用户是否能理解“继续正常打开 Codex”。
- 用户是否能找到 `历史` 入口。
- 固定三步是否能解决大多数历史显示问题。
- 历史真丢失反馈数量。
- 更新失败后是否能继续使用当前版本。
- 卸载恢复原生入口是否稳定。
- 用户误以为项目是官方项目的次数。
- 用户误以为工具会自动改 provider / `base_url` / 登录方式的次数。
- 用户请求 Codex++ parity 的类型。
- 用户是否尝试在 issue 中粘贴敏感内容。

## 9. 不应立刻变成新功能的反馈

下面反馈应先进入产品评估或路线图，不应在首发后立即扩功能：

- 插件市场。
- 云同步。
- provider 管理器。
- 上下文破限。
- 批量删除。
- 静默安装更新。
- 开机自启更新器。
- macOS 正式支持。
- EXE 安装器正式发布。
- 会话项目移动。
