# Codex Pro v0.3.0 实现护栏

## 1. v0.3.0 的唯一主目标

`v0.3.0` 的唯一主目标是让安装、更新、卸载更像普通 Windows 软件。

它不是功能堆叠版本，也不抢 `v0.4.0` 的 `Codex++` core parity 工作。

本阶段优先收口：

- 安装输出更低噪声。
- 安装后继续打开 `Codex` 的主路径更明确。
- 更新由用户确认触发。
- 更新前有备份和回滚说明。
- 卸载恢复原生 Codex 入口。
- 卸载默认保留 Codex 历史、历史快照和仓库代码。
- 维护入口和日常入口分离。

## 2. 不可变用户主路径

v0.3.0 不能改变下面主路径：

1. 安装一次。
2. 以后继续像平常一样打开 `Codex`。
3. Codex 内入口叫 `历史`。
4. `Codex Pro.cmd` 是维护 / 救援入口，不是新的日常入口。
5. 历史不完整时按固定三步：
   - 修复历史显示
   - 重建历史索引
   - 打开高级修复

任何新实现如果让用户误以为需要每天打开 `Codex Pro.cmd`，都应退回修改。

## 3. 不可变安全边界

v0.3.0 不允许突破这些边界：

- 不上传历史。
- 不上传账号数据。
- 不上传 `auth.json`。
- 不自动修改 `model_provider`。
- 不自动修改 `base_url`。
- 不自动切换登录方式。
- 不重写 `encrypted_content`。
- 不做批量删除。
- 不做静默更新。
- 不注册开机自启。
- 不注册后台更新器。
- 不把 compatibility mode 写成失败。
- 不承诺任意环境都能完整页面增强。

安装、更新、卸载输出必须继续让用户理解：Codex Pro 是本地优先的增强层，不是账号、provider 或云同步管理器。

## 4. 不可变 UI 原则

v0.3.0 不应扩大 Codex 内第一层 UI。

第一层原则：

- 一个入口。
- 一张救援卡。
- 一个主按钮。
- 高级默认折叠。
- 工程词不进第一层。
- hover / focus 才显示二级 row action。
- 当前会话不显示删除。

安装、更新、卸载体验可以更友好，但不能通过新增 Codex 内按钮、顶部菜单或功能广场来完成。

## 5. v0.3.0 允许改的范围

允许小步修改：

- 安装输出。
- 安装失败时的用户下一步提示。
- 更新检查和安装更新的确认文案。
- 更新前备份和失败回滚提示。
- 卸载提示。
- 卸载恢复失败时的下一步提示。
- `redaction` helper 的低风险接入。
- 文档一致性。
- 测试增强。
- 小范围 `service` / `inject-ui` 内部分区注释，但不得改变行为。

## 6. v0.3.0 不允许改的范围

v0.3.0 不做：

- 新插件平台。
- 插件市场。
- 云同步。
- macOS 正式支持。
- EXE 安装器正式发布。
- 批量删除。
- 自动 provider 切换。
- 上下文破限。
- 任意环境完整注入承诺。
- 静默安装更新。
- 开机自启更新器。
- 新的长期后台服务。
- 会话项目移动。
- 大规模目录重构。

如果某个改动需要触碰上述范围，应移出 v0.3.0，进入 roadmap 或 `Codex++` parity 矩阵重新评估。

## 7. 更新实现护栏

更新体验必须保持：

- 检查更新可以低噪声提示。
- 安装更新必须由用户确认。
- 更新前备份当前版本。
- 更新失败后尽量恢复当前版本。
- 更新完成后提示重新打开 `Codex`。
- 不注册后台更新器。
- 不注册开机自启。

错误文案优先告诉用户下一步，不应让用户以为当前版本已经不可用，除非确实无法恢复。

## 8. 安装实现护栏

安装体验必须保持：

- 安装完成第一层只看四行：
  1. 当前状态
  2. 日常入口
  3. 下一步
  4. 日志位置
- 安装输出必须说明继续正常打开 `Codex`。
- 安装输出必须说明 `Codex Pro.cmd` 是维护 / 救援入口。
- 安装输出必须说明不会改 `provider`、`base_url`、登录方式或 `encrypted_content`。
- 依赖、端口、CDP、bridge、SQLite 等细节只进日志或高级排障。

## 9. 卸载实现护栏

卸载体验必须保持：

- 先尝试恢复原生 Codex 入口。
- 移除 Codex Pro 创建的维护入口。
- 默认不删除 Codex 历史。
- 默认不删除历史快照。
- 默认不删除仓库代码。
- 只有显式 `-RemoveData` 才清理 Codex Pro 私有日志和数据。
- 如果恢复失败，必须告诉用户下一步，不得伪装成功。

## 10. 测试和验收

v0.3.0 每轮实现至少验证：

- `npm test -- --test-name-pattern "install|update|product-files|readme"`
- `node .\scripts\validate-install-smoke.mjs`
- `npm pack --dry-run --json`
- 隐私路径和旧口径扫描。

如果改了 JS，运行对应 `node --check`。

如果改了 PowerShell 脚本，运行脚本语法检查。

默认不运行真实 UI 验证；需要打开或重启真实 Codex 时必须人工确认。
